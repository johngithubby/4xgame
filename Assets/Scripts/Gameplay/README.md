# Gameplay Scripts

## Files

- `AutoShooter.cs`: Selects the nearest zombie ahead of the squad, applies automatic damage on a timer, rotates through the three imported survivor muzzles, aims the selected visible MPX rifle before sampling its barrel position, falls back to procedural aim/recoil only for generated test actors, and emits position-only and transform-aware shot events with the actual applied damage plus whether the origin came from a real muzzle.
- `FloatingFeedback.cs`: Animates short camera-facing world-space text feedback for gate, zombie, and shot outcomes, including a small shadow and cleanup for generated feedback materials.
- `GameplayVisuals.cs`: Defines shared prototype visual heights, optional fallback screen-space player marker sizing, visible world-space player rendering, inward gameplay lane spacing, disabled low gate footprints, gate card dimensions, humanoid zombie bounds, depth-safe combat feedback sizing, compact muzzle-flare sizing, a high-contrast weapon-origin tracer that remains shorter than the survivor footprint, legacy no-muzzle tracer fallback offsets, perspective chase-camera framing, and aspect-responsive camera FOV rules so the track, squad, gates, zombies, labels, flares, and tracers remain readable in runtime-generated scenes.
- `Gate.cs`: Applies a configured gate modifier when the player squad reaches the gate center, owns a per-gate material clone for marker tinting while preserving label font materials, then flashes resolved gate visuals briefly enough that the trailing camera cannot let old gates hide the player.
- `LevelDefinitionFactory.cs`: Creates eight small runtime mission definitions from local save progress, including readable finish spacing after the last obstacle, late armored zombie placements, damage multiplier gates, and mission-specific gate/zombie pacing.
- `LevelManager.cs`: Owns the Phase 1 level flow, collider-free runtime level spawning, stable per-level/per-index zombie appearance seeds with a non-repeating first-nine dominant palette cycle, muzzle-attached generated-weapon flares/tracers, fallback world-space shot effects, feedback labels, exact muzzle-origin effect starts for generated weapons, win/loss state, local coin, daily objective progress, mission completion/unlock, hero unlock, hero XP win reward claim, scene restart, and base return.
- `LevelState.cs`: Defines the minigame states used by gameplay and UI.
- `LevelStateEvaluator.cs`: Contains small testable rules for win/loss evaluation.
- `PhaseOneRuntimeBootstrap.cs`: Builds the playable Phase 1 prototype from a minimal scene at runtime, applies selected mission and HQ/hero save bonuses, preserves the factory-authored commander/scout/heavy SWAT models and renderer visibility, keeps both obsolete flat survivor cards suppressed, keeps the optional HUD-layer player marker disabled by default, lays out edge HUD text with anchor-matched pivots, keeps state text away from iPhone cutouts, and uses shared placeholder material creation for generated geometry.
- `PlayerSquad.cs`: Moves the squad forward, keeps the gameplay transform locked above the road, tracks squad count, tracks damage, pushes authoritative movement state to all imported character Animator bridges, and reports defeat. Its exact-name registry rotates through the commander, scout, and heavy's rendered rifles while excluding their hidden generated fallback anchors; generated-only tests retain their original muzzle behavior.
- `SimpleCameraFollow.cs`: Keeps the perspective camera locked to the moving squad from an angled chase view and refreshes camera FOV from the active screen aspect so fast lane changes, late gates, tall-phone framing, and finish-line motion stay visible without a top-down board view.
- `SquadLaneInput.cs`: Reads keyboard, pointer, touch, and on-screen button input to move the squad between lanes while ignoring raw pointer gestures over UI buttons.
- `Zombie.cs`: Tracks zombie type, health, armor-based damage reduction, defeat state, and squad loss when the squad reaches an undefeated zombie.

## Compile

Unity compiles these files automatically as part of the main runtime assembly.

## Behavior

The gameplay loop is intentionally small: the squad starts, moves forward, lane input chooses which gates and zombies matter, automatic shooting defeats zombies in the current lane, and the level ends when the squad reaches the finish or reaches zero members. One gameplay root still owns gate, zombie, shooting, camera, and finish rules, while three fully rendered imported Humanoids form its visible wedge. Their commander, scout, and heavy rifles each register a barrel-opening anchor and take turns steering the rigid MPX hierarchy from its live stock-to-muzzle line toward the current zombie; all obsolete generated anchors stay excluded from live shots.

Level construction derives each zombie's wardrobe seed from mission number, authored spawn order, lane, distance, and enemy type, producing random-looking but repeatable colours, tears, and missing gear without touching gameplay randomness. Runtime combat feedback uses compact muzzle-attached orange flares and tracer strips that begin at whichever survivor barrel fired, point along the same target line, compensate for FBX scale, and remain attached through the run cycle. The remaining gate, HUD, camera, reward, mission, hero-XP, zombie-breach, and end-state behavior is unchanged.
