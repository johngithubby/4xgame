# Gameplay Scripts

## Files

- `AutoShooter.cs`: Selects the nearest zombie ahead of the squad, applies automatic damage on a timer, rotates through registered survivor weapon muzzles when present, aims the imported leader's visible MPX rifle before sampling its barrel position, sends generated wing survivors the same target for procedural aim/recoil, and emits position-only and transform-aware shot events with the actual applied damage plus whether the origin came from a real muzzle.
- `FloatingFeedback.cs`: Animates short camera-facing world-space text feedback for gate, zombie, and shot outcomes, including a small shadow and cleanup for generated feedback materials.
- `GameplayVisuals.cs`: Defines shared prototype visual heights, optional fallback screen-space player marker sizing, visible world-space player rendering, inward gameplay lane spacing, disabled low gate footprints, gate card dimensions, humanoid zombie bounds, depth-safe combat feedback sizing, compact muzzle-flare sizing, a high-contrast weapon-origin tracer that remains shorter than the survivor footprint, legacy no-muzzle tracer fallback offsets, perspective chase-camera framing, and aspect-responsive camera FOV rules so the track, squad, gates, zombies, labels, flares, and tracers remain readable in runtime-generated scenes.
- `Gate.cs`: Applies a configured gate modifier when the player squad reaches the gate center, owns a per-gate material clone for marker tinting while preserving label font materials, then flashes resolved gate visuals briefly enough that the trailing camera cannot let old gates hide the player.
- `LevelDefinitionFactory.cs`: Creates eight small runtime mission definitions from local save progress, including readable finish spacing after the last obstacle, late armored zombie placements, damage multiplier gates, and mission-specific gate/zombie pacing.
- `LevelManager.cs`: Owns the Phase 1 level flow, collider-free runtime level spawning, stable per-level/per-index zombie appearance seeds with a non-repeating first-nine dominant palette cycle, muzzle-attached generated-weapon flares/tracers, fallback world-space shot effects, feedback labels, exact muzzle-origin effect starts for generated weapons, win/loss state, local coin, daily objective progress, mission completion/unlock, hero unlock, hero XP win reward claim, scene restart, and base return.
- `LevelState.cs`: Defines the minigame states used by gameplay and UI.
- `LevelStateEvaluator.cs`: Contains small testable rules for win/loss evaluation.
- `PhaseOneRuntimeBootstrap.cs`: Builds the playable Phase 1 prototype from a minimal scene at runtime, applies selected mission and HQ/hero save bonuses, creates three matching woman rifle survivor decals driven by hidden 3D animation rigs with compact visible raised rifle art carried inside the soldier footprint, rear-view soldier decals visible in the chase-camera minigame view plus approved front decals for zombie-side cameras, suppresses obsolete flat survivor cards, preserves factory-authored renderer visibility, keeps the optional HUD-layer player marker disabled by default, lays out edge HUD text with anchor-matched pivots, keeps state text away from iPhone cutouts, and uses shared placeholder material creation for generated geometry.
- `PlayerSquad.cs`: Moves the squad forward, keeps the gameplay transform locked above the road, tracks squad count, tracks damage, pushes authoritative movement state to imported character Animator bridges, and reports defeat. Its exact-name muzzle registry prefers the imported leader's rendered rifle and excludes hidden generated wing anchors so every live shot has a visible source; generated-only scenes keep round-robin firing.
- `SimpleCameraFollow.cs`: Keeps the perspective camera locked to the moving squad from an angled chase view and refreshes camera FOV from the active screen aspect so fast lane changes, late gates, tall-phone framing, and finish-line motion stay visible without a top-down board view.
- `SquadLaneInput.cs`: Reads keyboard, pointer, touch, and on-screen button input to move the squad between lanes while ignoring raw pointer gestures over UI buttons.
- `Zombie.cs`: Tracks zombie type, health, armor-based damage reduction, defeat state, and squad loss when the squad reaches an undefeated zombie.

## Compile

Unity compiles these files automatically as part of the main runtime assembly.

## Behavior

The gameplay loop is intentionally small: the squad starts, moves forward, lane input chooses which gates and zombies matter, automatic shooting defeats zombies in the current lane, and the level ends when the squad reaches the finish or reaches zero members. The gameplay squad transform drives gate, zombie, shooting, camera, and finish rules, while the licensed 3D SWAT leader provides the authoritative visible weapon during this technical trial. The imported leader registers a runtime muzzle anchor on the visible `SM_WP_Muzzle_011_01` barrel bone and steers the rigid `MPX` weapon hierarchy from the live imported stock-to-muzzle line toward the current zombie before each firing event; its obsolete generated leader muzzle and the two hidden generated wing anchors are excluded from live shot rotation. Generated-only scenes retain round-robin muzzle behavior. Level construction derives each zombie's wardrobe seed from mission number, authored spawn order, lane, distance, and enemy type, producing random-looking but repeatable colours, tears, and missing gear without touching gameplay randomness. Zombies shamble in place with their own bent-knee motion so lane threats feel alive before contact. Minigame HUD labels match text pivots to their anchors so top-left status text grows inward from its screen inset instead of clipping at the Game view edge, while the transient state label grows inward from the upper-right inset to avoid iPhone Dynamic Island captures. Gate visuals stay in tight portrait-safe gameplay lanes, skip low footprint decals for now, use high single-piece cards for readable modifier markers, and consume quickly after contact so a passed gate cannot sit between the chase camera and squad. Runtime combat feedback uses muzzle-attached scene feedback: compact orange flares and footprint-contained tracer strips begin at the visible barrel, point along the same target line as the weapon, compensate for the imported FBX hierarchy scale so their authored world size remains readable, use always-visible solid foreground materials, and stay glued to that muzzle through the run cycle; the older forward/lane offset remains only for no-muzzle fallback shots. Floating TextMesh damage/gate/breach labels billboard to the camera, draw through scene depth, and carry a small world-space shadow for iOS readability. Zombies are generated as humanoid bodies with green heads, faces, reaching arms, legs, feet, and wounds; armored zombies add helmet, chest, shoulder, strap, and belt pieces plus a small `ARMOR` label and reduced incoming shot damage so side-lane threats are visible and mechanically distinct before the player reaches them. A wider angled chase camera keeps those side-lane actors in view without reverting to an overhead board view, and extra-tall portrait devices receive a controlled vertical-FOV increase so side lanes keep the same horizontal coverage as the reference phone framing. A win grants one local coin reward for that run, advances the local daily objective, marks the cleared mission complete, can unlock the next mission when clearing the highest unlocked mission, can grant the first hero, awards equipped-hero XP, and saves before the player returns to Base. HQ progression still provides squad bonuses, while mission progression selects among eight local layouts.
